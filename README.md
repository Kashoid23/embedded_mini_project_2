## Обладнання

- **STM32F411CEU6** + ST-Link V2
- світлодіоди: 2 червоні, 1 жовтий, 2 зелені
- резистори: 5 × 220 Ω
- пасивний buzzer + NPN-транзистор (S8050 / BC547) + резистор 1 кОм + діод 1N4148
- тактова кнопка (кнопка пішохода)
- модуль реле **JQC-3F-05VDC-C**
- окреме джерело **5 В DC** для реле

## Як це працює

### 1. Ідея

У Японії послідовність кольорів світлофора відрізняється від української: немає миготливого зеленого для авто і немає «червоний + жовтий». Авто їдуть на зелений, доки пішохід не натисне кнопку:

| Фаза | 1 | 2 | 3 | 4 | 5 | 6 |
|---|:---:|:---:|:---:|:---:|:---:|:---:|
| **Тривалість** | ≥ 10 с, чекає кнопку | 3 с | 2 с | 8 с | 4 с | 2 с |
| **Авто** | 🟢 | 🟡 | 🔴 | 🔴 | 🔴 | 🔴 |
| **Пішохід** | 🔴 | 🔴 | 🔴 | 🟢 | 🟢 блимає | 🔴 |
| **Звук** | | | | ピヨ・ピヨピヨ | | |

Після фази 6 цикл повертається до фази 1. Фази 3 і 6 — «усі червоні»: час, щоб перехід звільнився, перш ніж рух отримає зелений.
Уся програма працює без `HAL_Delay()`. Таймер TIM2 щомілісекунди збільшує лічильник, а superloop на кожному проході перевіряє кнопки, оновлює світлофор і звук. Тому кнопка реагує миттєво навіть під час звуку.

**Безпека.** Катоди червоних і зелених LED йдуть на GND не напряму, а через контакт реле. Реле увімкнене, лише доки програма активно тримає його. При будь-якому збої реле відпускає, і червоні й зелені фізично гаснуть. Жовтий підключений прямо до GND, тому лише він може світитися: блимає раз на секунду, як нічний режим японського світлофора.

### 2. Налаштування CubeMX і чому саме такі

#### Тактування: HSE, 96 МГц

Кварц 25 МГц → PLL (M = 25, N = 192, P = 2) → **96 МГц**. APB1 ділимо на 2 (максимум для шини 50 МГц), але таймери на APB1 отримують подвоєну частоту:

```
48 МГц × 2 = 96 МГц  →  TIM2 і TIM3 тактуються від 96 МГц
```

#### TIM2: системний тик 1 мс

- Prescaler = **96 − 1**
- Counter Period = **1000 − 1**
- **TIM2 global interrupt** увімкнено

```
96 000 000 Гц / 96 = 1 000 000 Гц  →  1 такт = 1 мкс
1000 тактів × 1 мкс = 1 мс         →  переривання щомілісекунди
```

У перериванні збільшується `s_ms_ticks`. Це «годинник» усієї програми: світлофор, кнопки і звук рахують час як різницю `now_ms - t_start_ms`.

#### TIM3: PWM для buzzer'а, PA6

- PWM Generation **CH1**, PWM mode 1
- Prescaler = **96 − 1** → лічильник 1 МГц
- Pulse = **0** → після старту тиша

Пасивний buzzer звучить, лише коли його смикати з потрібною частотою. Таймер генерує меандр апаратно, а код лише змінює частоту:

```
ARR = 1 000 000 / частота − 1      (2800 Гц → ARR = 356)
CCR = (ARR + 1) / 2                → заповнення 50 %, найгучніше
CCR = 0                            → тиша
```

#### GPIO: світлодіоди PB13, PB14, PB15, PB0, PB1

Output Push-Pull, Output level **Low**: після старту всі LED вимкнені. User Label (`VEH_RED`, `VEH_YELLOW`, `VEH_GREEN`, `PED_RED`, `PED_GREEN`) робить так, що в коді немає номерів пінів, лише імена з `main.h`.

#### PA1 (PED_BTN) і PA0 (FAULT_KEY): EXTI, Falling edge, Pull-up

Кнопка замикає пін на GND. Pull-up тримає `HIGH`, натискання дає `LOW`, тобто спадаючий фронт. PA0 — це кнопка **KEY** на самій платі, вона імітує збій. Різні піни мають різні лінії EXTI (0 і 1), тож у кожної кнопки своє переривання.

#### PB12 (RELAY_EN): Output Open Drain, Output level High

Модуль реле вмикається **низьким** рівнем. **Open Drain** означає, що пін вміє лише притягнути лінію до GND або відпустити її. Коли PB12 відпускає лінію, модуль сам підтягує IN до своїх 5 В, і реле надійно вимикається. У режимі Push-Pull пін видавав би лише 3,3 В, а для модуля на 5 В цього мало. PB12 витримує 5 В (FT), тому так можна.

`High` на старті означає, що реле вимкнене, доки програма його не ввімкне.

#### IWDG: Prescaler 32, Reload 500

Незалежний watchdog працює від окремого генератора LSI (~32 кГц):

```
32 000 / 32 = 1000 Гц  →  500 / 1000 = 0,5 с
```

Якщо superloop 0,5 с не «погодує» watchdog, мікроконтролер перезавантажиться і стартує одразу в безпечному режимі.

#### NVIC

| Переривання | Пріоритет | Навіщо |
|---|---|---|
| TIM2 global interrupt | 1 | тик 1 мс не повинен губитися |
| EXTI line0 | 2 | кнопка KEY |
| EXTI line1 | 2 | кнопка пішохода |

### 3. Код у `main.c`, по порядку виконання

#### `Includes`
```c
#include "button.h"
#include "buzzer.h"
#include "traffic_light.h"
```
Підключаємо три модулі: кнопки, звук і світлофор.

#### `PV`
```c
static volatile uint32_t s_ms_ticks = 0U;
static button_t s_btn_pedestrian;
static button_t s_btn_fault;
```
- `s_ms_ticks` — мілісекунди від старту. `volatile`, бо його змінює переривання.
- Дві кнопки — два екземпляри однієї структури, код для них спільний.

#### `0`
```c
static uint32_t custom_millis(void) { return s_ms_ticks; }
```
Поточний час у мс. Читання 32-бітної змінної на Cortex-M4 атомарне, тому забороняти переривання не потрібно.

#### `2`: старт

```c
const bool reset_by_watchdog = (__HAL_RCC_GET_FLAG(RCC_FLAG_IWDGRST) != 0U);
__HAL_RCC_CLEAR_RESET_FLAGS();
__HAL_DBGMCU_FREEZE_IWDG();
```
Читаємо, чи останнє перезавантаження спричинив watchdog, і очищаємо прапорці. `FREEZE_IWDG` зупиняє watchdog, коли дебагер ставить програму на паузу. Без цього брейкпоінт довший за 0,5 с перезавантажував би плату.

```c
button_init(&s_btn_pedestrian, PED_BTN_GPIO_Port, PED_BTN_Pin);
button_init(&s_btn_fault, FAULT_KEY_GPIO_Port, FAULT_KEY_Pin);
buzzer_init(&htim3, TIM_CHANNEL_1);
(void)HAL_TIM_Base_Start_IT(&htim2);
```
Налаштовуємо кнопки, запускаємо PWM (поки тихо) і тик 1 мс.

```c
tl_init(custom_millis());
if (reset_by_watchdog) {
    tl_set_fault(TL_FAULT_WATCHDOG, custom_millis());
}
```
Запускаємо світлофор. Якщо плата щойно перезавантажилась через зависання, одразу переходимо в безпечний режим.

#### `WHILE`
```c
const uint32_t now = custom_millis();

button_update(&s_btn_pedestrian, now);
button_update(&s_btn_fault, now);

if (button_take_press(&s_btn_pedestrian)) { tl_request_crossing(); }
if (button_take_press(&s_btn_fault))      { tl_set_fault(TL_FAULT_ERROR, now); }

tl_update(now);
buzzer_update(now);

(void)HAL_IWDG_Refresh(&hiwdg);
```
Кожен прохід робить три кроки: читає входи, оновлює логіку й виходи, «годує» watchdog. Жодна функція не чекає, тому прохід триває мікросекунди.

#### `4`: callback-и переривань

```c
void HAL_TIM_PeriodElapsedCallback(...)  → s_ms_ticks++;
```
Викликається щомілісекунди від TIM2. Перевірка `htim->Instance == TIM2` гарантує, що рахуємо саме наш таймер.

```c
void HAL_GPIO_EXTI_Callback(...)  → button_on_edge_irq(...);
```
Переривання від кнопки лише ставить прапорець «на піні щось сталося». Уся логіка виконується пізніше в superloop: переривання має бути коротким.

### 4. Що роблять модулі

#### `button.c`: debounce через скінченний автомат

Механічна кнопка при натисканні «дріботить»: одне натискання = 5–20 імпульсів. Автомат чекає 20 мс і перечитує пін:

| Стан | Чекає | Перехід |
|---|---|---|
| `IDLE` | прапорець від EXTI | → `DEBOUNCE_PRESS` |
| `DEBOUNCE_PRESS` | 20 мс | пін `LOW` → `PRESSED` + подія; `HIGH` → `IDLE` (шум) |
| `PRESSED` | пін став `HIGH` | → `DEBOUNCE_RELEASE` |
| `DEBOUNCE_RELEASE` | 20 мс | `HIGH` → `IDLE`; `LOW` → `PRESSED` (дрібезг) |

Одне фізичне натискання дає рівно одну подію. `button_take_press()` повертає її один раз і скидає.

#### `traffic_light.c`: скінченний автомат світлофора

| Стан | Авто | Пішохід | Звук | Тривалість | Далі |
|---|---|---|---|---|---|
| `STARTUP` | червоний | червоний | — | 3 с | `VEH_GREEN` |
| `VEH_GREEN` | зелений | червоний | — | ≥ 10 с, чекає кнопку | `VEH_YELLOW` |
| `VEH_YELLOW` | жовтий | червоний | — | 3 с | `ALL_RED_TO_PED` |
| `ALL_RED_TO_PED` | червоний | червоний | — | 2 с | `PED_GREEN` |
| `PED_GREEN` | червоний | зелений | ピヨ・ピヨピヨ | 8 с | `PED_GREEN_BLINK` |
| `PED_GREEN_BLINK` | червоний | зелений блимає | — | 4 с | `ALL_RED_TO_VEH` |
| `ALL_RED_TO_VEH` | червоний | червоний | — | 2 с | `VEH_GREEN` |
| `SAFE_FLASH` | жовтий блимає | темний | — | до RESET | — |

Запит пішохода приймається в станах `STARTUP`, `VEH_GREEN` і `ALL_RED_TO_VEH`. В інших станах цикл для пішохода вже йде.

Дві функції роблять усю роботу:
- `led_fsm()` — дії **при вході** в стан: виставити LED, увімкнути чи вимкнути звук, запам'ятати час входу.
- `tl_update()` — **умови виходу**: чи минув час, чи є запит від пішохода; також блимання.

```c
static void leds_set (const tl_led_pattern_t *pattern) {
	leds_set_state(pattern, false);
	leds_set_state(pattern, true);
}
```
**Break-before-make:** спершу гасимо зайві LED, потім вмикаємо потрібні. Два конфліктні сигнали не світяться разом навіть мікросекунду.

```c
void tl_set_fault (tl_fault_t fault, uint32_t now_ms) {
	if (s_tl.state == TL_STATE_SAFE_FLASH) { return; }
	relay_set(false);
	...
}
```
Безпечний режим: **спочатку** відпускаємо реле (апаратний захист), потім змінюємо стан. Повторний виклик нічого не робить, тож зберігається перша причина. Вийти можна лише через RESET.

```c
const bool blink_on = ((elapsed / T_BLINK_HALF_PERIOD_MS) % 2U) == 0U;
```
Блимання без окремого таймера: `elapsed / 500` дає номер півперіоду. Парний — світить, непарний — ні.

#### `buzzer.c`: японський звук «ピヨ・ピヨピヨ»

У Японії на переходах звучить перекличка пташок (異種鳴き交わし): з одного боку «ピヨ», з другого у відповідь «ピヨピヨ». Звук — таблиця кроків «частота + тривалість»:

| Момент | Звук |
|---|---|
| 0 мс | «ピヨ» — 130 мс |
| 1300 мс | «ピヨ» — 130 мс |
| 1520 мс | «ピヨ» — 130 мс |
| 2800 мс | цикл повторюється |

Кожне «ピヨ» — 5 кроків по 26 мс: 2800 → 2550 → 2300 → 2050 → 1800 Гц. Тон спадає, як у пташки. Ритм узято з патенту Koito (US 6,127,943), висоти тонів — наближення.

```c
s_t_step_ms += crossing_tone[s_step].dur_ms;
s_step = (s_step + 1U) % CROSSING_TONE_STEPS_COUNT;
```
`+=` замість `= now_ms` тримає ритм рівним: запізнення superloop не накопичуються. `%` закільцьовує звук.

### 5. Що відбувається з часом

| Час | Що відбувається |
|---|---|
| 0 с | `tl_init()`: усі червоні, реле клацає |
| 3 с | зелений для авто |
| будь-коли | пішохід натискає кнопку → запит запам'ятано |
| ≥ 10 с зеленого | жовтий 3 с |
| +3 с | усі червоні 2 с |
| +2 с | зелений для пішохода, «ピヨ・ピヨピヨ» 8 с |
| +8 с | зелений пішохода блимає 4 с, звук вимкнено |
| +4 с | усі червоні 2 с, потім зелений для авто |
| KEY | реле відпускає, червоні й зелені гаснуть, жовтий блимає |
| зависання | watchdog → reset → одразу безпечний режим |

### 6. Як перевірити швидко

У `config.h`:
```c
#define T_VEH_GREEN_MIN_MS  3000U
```
Після натискання кнопки пішохода цикл стартує через 3 с замість 10.

- 10 швидких натискань під час зеленого → цикл запускається лише раз.
- KEY у будь-якій фазі → реле клацає, світиться лише блимаючий жовтий.
- Від'єднати 5 В від реле під час зеленого → зелений фізично гасне.
- Логічний аналізатор на PB15 і PB1 → ніколи не `HIGH` одночасно.

## Запуск

1. Відкрити проєкт у STM32CubeIDE.
2. За потреби поставити короткі часи у `config.h`.
3. **Project → Build Project**.
4. **Debug**, потім **Resume**, і додати `s_ms_ticks` у Live Expressions.
